1. 適用範圍

本政策適用於 Chrome 擴充功能「雲端懷爾抓抓（medicloud2-fhir-bridge）」（以下稱「本擴充功能」）。本擴充功能協助依法且已獲授權的醫事人員，在健保醫療資訊雲端查詢系統（MediCloud）目前病人的情境中，取得臨床參考資料、於使用者瀏覽器內轉換為 HL7 FHIR R4 Bundle，並由使用者下載或交給 MediPrisma 的本機匯入流程。

本擴充功能不是由衛生福利部中央健康保險署製作、授權或背書，也不會繞過或取代 MediCloud 的機構、醫事人員、讀卡、病人或其他驗證。

2. 本擴充功能處理的資料

本擴充功能不另外顯示首次同意彈窗或增加確認按鈕。使用者開啟工具列 popup 時，程式會確認 MediCloud 目前顯示的病人，以呈現可操作狀態；使用者點擊「取得雲端病歷資料」、「下載原始資料」、MediCloud 頁面 Logo，或以明確的 WinForms control URL 啟動流程後，才依所選功能取得臨床內容、轉換、下載或交給 MediPrisma。相關資料處理方式統一記載於本政策：

  • 個人識別資料：姓名、身分證字號／居留證或其他雲端病歷病人證號（去識別化預設關閉；啟用時，畫面與 FHIR 證號使用遮罩值；關閉時保留健保頁面提供的姓名、證號與完整生日，不再額外遮罩；下載檔名仍使用遮罩證號；原始 API 回應可能仍含直接識別）、出生日期、性別，以及用於防止病人混淆、由隨機 session key 計算的 HMAC-SHA-256 patient context。該值仍視為 pseudonymous PHI，不是匿名資料。
  • 健康與醫療資料：就醫、用藥、檢驗、檢查、影像／病理文字報告、牙科處置、過敏、手術、特材紀錄、出院病摘、復健、餘藥、成人預防保健、癌症篩檢及相關臨床參考資料；特材紀錄包含名稱、代碼、許可證、型號／規格、診療部位、數量及來源申報資訊。使用者啟用即時影像調閱時，FHIR 可能包含調閱所需的來源識別描述，但不包含新簽發的短效 Viewer URL。
  • 驗證資訊：頁面載入起，程式會在 MediCloud 頁面的記憶體 closure 中觀察既有同來源 API 授權請求；只保留可綁定目前病人的授權最多 30 分鐘，於使用者啟動取得時使用，僅向同一個 https://medcloud2.nhi.gov.tw 來源提出必要請求。
  • 網站內容：MediCloud 目前病人頁面中辨識病人情境所需的內容，以及使用者啟動後取得的同來源 API 回應。
  • 操作設定與技術狀態：去識別化偏好、整合偏好、可信來源識別、經驗證的 MediPrisma 目的地、工作識別碼、執行狀態、時間、資料大小、資源筆數、遮罩檔名、分頁識別碼與不含原始病歷內容的錯誤代碼。

本擴充功能不蒐集或建立一般瀏覽紀錄、位置、付款資料、個人通訊、廣告識別碼、分析事件或跨網站追蹤資料。

3. 使用目的

上述資料只用於本擴充功能揭露的單一用途：

  1. 確認使用者目前操作的 MediCloud 病人。
  2. 取得使用者在該工作階段有權查看的臨床參考資料。
  3. 進行 schema、完整性、病人隔離與 FHIR reference 檢查。
  4. 在瀏覽器內轉換為 FHIR R4 Bundle。
  5. 依使用者選擇下載 FHIR JSON、下載原始回應，或交給 MediPrisma 的本機匯入流程。
  6. 顯示工作進度、錯誤與結果，並在期限到達時清除暫存。

資料不會用於廣告、行銷、資料仲介、信用評估、放款、建立使用者側寫或與上述單一用途無關的模型訓練。

4. 資料來源與流向

4.1 MediCloud

急診網址捷徑入口會在擴充功能內以 JavaScript 對話框詢問本次授權查詢病人的證號與民國七碼生日。取消或格式不合法時不啟動。資料以內部訊息送至背景程式，不放入網址、不在輸入頁保存，也不傳給發布者；後續使用相同的官方急診登入、預填查詢、病人核對與短效記憶體流程。手填生日標記為使用者輸入來源，不宣稱由 HIS 提供或由健保驗證；此入口不設定院所路由標記。輸出生日仍遵循既有去識別設定。

使用者啟用經授權的臨床資料補充時，本擴充功能可將本次查詢所需的姓名、可辨識證號、生日與短效工作識別傳至使用者設定且通過來源驗證的本機資料提供端，以核對同一病人並取得獲准調閱的 SOAP、診斷、用藥、醫囑及報告。補充資料經核對後併入同一份 FHIR 結果，沿用相同加密暫存、保存期限與清除規則；不交換來源系統的登入 cookie。啟用去識別化時，不擷取尚無相同遮罩保證的補充原文。無法核對或取得補充資料時，保留可用的雲端結果並說明原因。個資不放入啟動網址、不記錄於 console，也不傳給發布者。

雲端資料來源為使用者已登入且有權查看的 https://medcloud2.nhi.gov.tw。驗證資訊只用來向同一來源提出本次必要請求；不會回傳給 extension 背景程式、不會寫入 storage、不會放進下載檔、不會由 extension 記錄，也不會傳給 MediPrisma 或發布者。API 請求包含 MediCloud 的存取紀錄參數；MediCloud 可能依其規範記錄使用者的查詢，該紀錄由 MediCloud／健保署管理，不會提供給本 extension 發布者。

4.2 使用者下載

使用者可以主動下載：

  • FHIR JSON：依使用者的去識別化設定產生；仍可能包含敏感個人或健康資料及健保影像即時調閱描述。短效 Viewer URL 只用於立即開啟通過 HTTPS nhi.gov.tw／*.nhi.gov.tw 驗證的分頁，不寫入 JSON。
  • RAW DATA：未轉換的來源回應，不套用 FHIR 去識別化設定，可能包含直接識別與完整臨床內容。

檔案建立後由瀏覽器交給使用者裝置的下載功能；下載後的保存、傳輸與刪除由使用者及其所屬機構負責。

4.3 MediPrisma

使用者選擇或點擊「取得病歷並送到 MediPrisma」時，本擴充功能會依使用者設定開啟允許的 https://mediprisma.tw/app/ 或 https://mediprisma.tw/app-hmc/ 工作區分頁，並將該次 FHIR Bundle 交給該頁的本機檔案匯入元件。Bundle 只包含穩定的健保影像即時調閱描述，不包含短效 Viewer URL。使用者之後點擊影像動作時，Bridge 才向同一位病人的 MediCloud 工作階段取得新 URL，驗證 HTTPS、無 credentials／自訂 port 及 nhi.gov.tw DNS 網域邊界後立即開啟；URL 不回傳 MediPrisma、不寫入 FHIR 或 storage。Bundle 本身不放入交接頁網址、查詢參數、hash、頁面 global 或可見 DOM 文字。MediPrisma 確認匯入後，本擴充功能仍會在既有期限內保留暫存副本，方便再次查看或下載。

MediPrisma 是接收資料的獨立應用介面。匯入後使用者若在 MediPrisma 啟用 AI 或其他雲端功能，後續處理不再由本擴充功能控制，應以 MediPrisma 當時顯示的揭露、使用者選擇與所屬機構規範為準。

醫析的本機資料比對功能可按需請求同次原始回應。擴充功能僅接受允許的醫析頁面以目前匯入的 Bundle ID 請求，確認原健保分頁仍為同一病人後，將 IndexedDB 暫存解密並分段傳回發出請求的文件。原始回應不套用 FHIR 去識別化，可能含直接識別資料；不得將讀取等同於同意上傳錯誤回報。讀取不會重新擷取、不會展延原一小時期限，本擴充功能不自動上傳原始回應或錯誤回報。醫析接收後的本機比對及使用者選擇的回報流程，依醫析當時顯示的內容與選擇處理。

4.4 發布者與其他第三方

本擴充功能沒有發布者後端、分析工具、遙測、錯誤回報服務、廣告 SDK、追蹤像素或遠端程式碼。發布者不會透過本擴充功能接收病人資料、FHIR Bundle、RAW DATA、Bearer authorization 或使用紀錄。

除前述使用者主動啟用的臨床資料取得、MediPrisma 匯入與本機比對、依法必須配合、處理安全事件，或取得使用者對特定資料的明確同意外，本擴充功能不向第三方提供資料。

5. 本機儲存與保存期間

  • 原始 MediCloud 回應：擷取期間只在執行記憶體中處理。「取得雲端病歷資料」成功後，該次擷取的原始回應會與 FHIR Bundle 一起以 gzip 壓縮及 AES-256-GCM 加密存於同一筆 IndexedDB 記錄，使「下載原始資料」不需重新讀取雲端病歷；其 runId、病人 context、保存期限與清除時點與 Bundle 完全相同（見下方「Bundle 清除時點」）。輸出前會即時再確認 MediCloud 目前顯示的病人，不符時一律清除暫存且不產生檔案。使用者未先執行轉換而直接點選「下載原始資料」時，該次擷取只在記憶體中處理，下載後不保存。
  • 轉換失敗時的原始回應：若已取得來源回應且再次核對為同一病人，可將該次原始回應壓縮加密後暫存，供使用者下載排查；最長一小時，並沿用相同病人綁定及清除規則。取消工作或病人核對失敗時不保留。
  • Bearer authorization：只存在 MediCloud 頁面的記憶體 closure，最多 30 分鐘或更早的已知到期時間；病人切換、換卡／登出、頁面離開或擷取授權遭拒後失效。病人標頭尚不可辨識時不保存該次觀察到的授權。
  • 待處理 FHIR Bundle：gzip 壓縮及 AES-256-GCM 加密後存於擴充功能專用 IndexedDB，使用 unlimitedStorage 支援大型 Bundle，最長 1 小時；chrome.storage.session 保存工作狀態與短效解密金鑰；IndexedDB 無法使用時，可另保留最多 3 MiB 的加密結果作為 session 備援，沿用相同病人綁定、到期及清除規則。原始回應過大時可不保留，但不截斷主要結果。
  • Bundle 清除時點：新工作／病人切換取代、到期、使用者明確清除、擴充功能更新，或瀏覽器工作階段結束後下次啟動清理，以先發生者為準；下載與 MediPrisma 匯入不會清除暫存副本。同一筆記錄內保留的原始回應一併清除，不會單獨留存。
  • 工作狀態：工作識別碼、病人 context hash、遮罩檔名、時間、摘要、分頁識別碼與錯誤狀態可在同一瀏覽器工作階段內保留，以便恢復進度或顯示結果；下一次工作、清除或 session 結束時移除。
  • 本機偏好：去識別化、整合偏好、可信來源識別及經驗證的 MediPrisma 目的地保存在 chrome.storage.local，直到使用者更改、清除擴充功能資料或移除本擴充功能。升級時可讀取舊版 localStorage 的去識別化偏好進行遷移；遷移或讀取失敗時保留遮罩。這些設定不含病歷內容，也不存入同步儲存。
  • 本擴充功能不建立或保存 persistent consent record；v0.5.6 起，啟動時會刪除舊版留下的兩欄同意紀錄。除這次相容性清理外，不使用 chrome.storage.local 或 chrome.storage.sync 保存病人、健康或同意資料；資料不會同步到使用者的 Google 帳號。

6. 安全措施

本擴充功能採取下列措施：

  • 權限只限 medcloud2.nhi.gov.tw 與 mediprisma.tw，不要求 <all_urls>。
  • 所有跨網站連線均使用 HTTPS。
  • 開始前、擷取中及完成後驗證病人情境；偵測到切換病人即停止並作廢結果。
  • 驗證資訊不離開 MediCloud 頁面記憶體閉包。
  • FHIR 暫存限制大小、期限與可讀取的 extension context。
  • MediPrisma 交接只接受允許的 HTTPS 工作區、同一接收文件與同一工作；每次資料出口前重新確認目前 MediCloud 病人。
  • 現行 private/internal build 的固定預加密 MediPrisma credential 仍有 replay 風險，不符合正式上線標準。正式版必須先撤銷底層 credential，改成綁定 user/session/audience/challenge/expiry 且有 replay protection 的 server-minted single-use token。
  • 不將臨床內容、病人識別或登入授權放入交接網址、log、分析事件或工作完成通知。影像短效網址只供核對後立即開啟，不寫入 FHIR 或暫存。
  • 不下載或執行遠端程式碼。

沒有任何安全措施能保證零風險。使用者不得在未受控的共用電腦上處理病人資料，並應依所屬機構政策保護下載檔。

7. 使用者選擇、查詢與刪除

  • 不啟動功能：本擴充功能不會擷取臨床內容。
  • 不使用 MediPrisma：可選擇只下載 FHIR JSON；若不希望產生檔案，可不下載並等待暫存到期。
  • 清除 extension 暫存：使用者按下明確移除、新工作／病人切換取代、最長一小時到期、關閉瀏覽器工作階段，或移除 extension；完成下載或 MediPrisma 交接不會立即清除，方便再次操作。暫存的 FHIR Bundle 與同一次擷取保留的原始回應存於同一筆記錄，上述任一時點都會一併清除，不會只留下其中一項。
  • 刪除已下載檔案：由使用者在作業系統中刪除；發布者無法存取或代為刪除。
  • 查詢發布者持有的資料：發布者不透過本擴充功能接收個別使用者或病人的資料，因此通常沒有可供查詢、更正或刪除的伺服器端紀錄。

如需支援，請勿透過一般電子郵件、公開 issue 或截圖傳送真實病人資料、完整身分證字號、病歷內容、登入憑證或 token。

8. 兒童資料

本擴充功能不是直接提供給兒童的一般消費者服務。具權限醫事人員可能依法在診療情境中處理未成年病人的資料；該處理仍受相同的用途限制、安全措施、機構政策與適用法律規範。

9. 臨床與法律限制

MediCloud 資料與本擴充功能輸出均供臨床參考。本擴充功能不提供診斷或治療建議，也不會使來源資料自動成為院內正式病歷。使用者應以官方來源、專業判斷及所屬機構的確認、簽章與病歷保存流程為準。

10. Chrome Web Store Limited Use

本擴充功能對使用者資料的使用遵守 Chrome Web Store User Data Policy，包括 Limited Use 要求。資料只用於提供或改善已揭露的單一用途；除政策允許且必要的情形外，不移轉、出售或供人員讀取，也不用於個人化廣告、資料仲介或信用評估。

The use of information received by this extension will adhere to the Chrome Web Store User Data Policy, including the Limited Use requirements.

11. 政策變更

如資料類別、用途、分享對象、保存方式或權限有實質變更，發布者會在變更生效前更新本頁日期與公開產品資訊，並依適用的 private deployment 或未來 Public 發布規範處理。現行 private build 不因此新增自訂同意彈窗或確認按鈕。

Extension version: 0.15.4

Effective date: July 31, 2026

Publisher: medcloud2-fhir-bridge project (GitHub: voho0000)

Privacy and support contact: https://github.com/voho0000/voho0000.github.io/issues/new

Published policy URL: https://mediprisma.tw/medcloud2-fhir-bridge/privacy/

GitHub backup: https://voho0000.github.io/medcloud2-fhir-bridge/privacy/

1. Scope and purpose

medicloud2-fhir-bridge (雲端懷爾抓抓) is a Chrome extension for authorized healthcare professionals. Its single purpose is to obtain clinical reference data for the patient currently displayed in Taiwan NHI MediCloud, convert that data locally into an HL7 FHIR R4 Bundle, and let the user download the result or hand it to MediPrisma's browser-local import flow.

The extension is not produced, authorized, or endorsed by Taiwan's National Health Insurance Administration. It does not bypass MediCloud authentication or access controls.

2. Data handled

The extension does not add a first-use consent dialog or extra confirmation buttons. Opening the toolbar popup checks the patient currently displayed by MediCloud so the interface can show the correct workflow state. Clinical content is retrieved, converted, downloaded, or handed to MediPrisma only after the user chooses an existing capture, raw-download, or in-page launcher action, or starts an explicit WinForms control-URL flow. The handling is described in this policy:

  • Identifiers: name, national ID, resident or other MediCloud patient identifier (de-identification is off by default; enabling it masks display and FHIR identifiers; leaving it disabled preserves the source name, identifier and full birth date without additional masking; filenames remain masked, while raw API responses may still contain direct identifiers), date of birth, sex, and a patient-context HMAC-SHA-256 keyed by a random session-only secret. It prevents patient mixing and offline guessing but remains pseudonymous health information rather than anonymous data.
  • Health information: encounters, medications, laboratory and examination records, reports, dental procedures, discharge summaries, rehabilitation, remaining medication days, preventive care, cancer screening, allergies, surgeries, special-material claims and inferred material-to-surgery relationships, related clinical reference data, and stable imaging-request descriptors. A short-lived NHI Viewer URL is requested only after the user clicks an image-viewer action and is opened directly without being saved in the exported file.
  • Authentication information: existing same-origin MediCloud API authorization is observed from page load in a page-memory closure. Only authorization bound to the currently identifiable patient is retained, for at most 30 minutes or an earlier known expiry, and used for necessary same-origin requests after the user starts capture. It is invalidated on a patient change, card change/logout, page exit, or capture authorization rejection.
  • Website content: the minimum current-patient page content and same-origin API responses needed for the requested feature.
  • Local preferences and job metadata: de-identification and integration preferences, trusted-source identifiers, validated MediPrisma destination, job IDs, timestamps, sizes, resource counts, masked filenames, tab IDs, status, and non-clinical error codes.

The extension does not collect general browsing history, location, payment data, personal communications, advertising identifiers, analytics events, or cross-site tracking data.

3. Use and sharing

The ER shortcut asks for the authorized patient's identifier and seven-digit ROC birth date inside the extension. Cancelled or invalid input does not start a query. These values are held in memory for the requested official card-login and patient-query flow, are not placed in a launch URL or saved by the input page, and are not sent to the publisher. Pending login and query are limited to two minutes; a worker restart requires a fresh request. Birth dates entered manually are marked as user-entered rather than independently verified, and output follows the de-identification setting.

When the user enables authorized clinical-data supplementation, the extension may send the name, visible identifier, birth date and short-lived job identifiers needed for the current query to the user-configured, source-validated local data provider. It verifies the same patient before receiving authorized SOAP notes, diagnoses, medications, orders and reports. Verified data is merged into the same FHIR result under the same encryption, retention and clearing rules. Source-system login cookies are not exchanged. When de-identification is enabled, supplemental free text without an equivalent masking guarantee is not retrieved. If supplementation is unavailable or cannot be verified, usable MediCloud results remain available with an explanation.

Data is used only to verify the current patient, retrieve authorized MediCloud data, perform safety and FHIR validation, convert it to FHIR R4, display progress, delete expired results, and complete the user's selected download or MediPrisma import.

The publisher does not receive patient data, Bundles, raw responses, authorization values, or telemetry. Necessary MediCloud API requests include its access-log parameter, so MediCloud may record the authorized user's query under its own policies; those logs are controlled by MediCloud/NHIA and are not provided to the extension publisher. The extension contains no publisher backend, analytics, advertising, tracking, error-reporting SDK, or remote code.

When the user chooses MediPrisma, the extension passes the Bundle once to the local file-import control in the configured, allowed https://mediprisma.tw/app/ or https://mediprisma.tw/app-hmc/ workspace. The Bundle contains only a stable NHI imaging-request descriptor, not a short-lived Viewer URL. After a later user image action, the Bridge obtains a fresh URL from the same-patient MediCloud session, validates it as HTTPS, free of credentials or a custom port, and hosted at nhi.gov.tw or a true subdomain, then opens it directly. The URL is not returned to MediPrisma, written to FHIR, or stored. Subsequent use of MediPrisma, including any optional cloud or AI feature, is outside this extension's control and is subject to the disclosure shown by MediPrisma at that time, the user's choices, and the user's organizational rules.

4. Local retention

MediPrisma may request the original responses for local comparison using the exact imported Bundle ID. The extension checks its allowed application route, requesting document, original expiry, and current patient in the source MediCloud tab before delivery. Responses are decrypted locally and transferred in bounded chunks; partial transfers are not released to the page. Reading never recaptures data or extends the existing one-hour limit. Original responses are not de-identified by the FHIR name preference. The extension does not automatically upload originals or error reports; any later report is a separate MediPrisma user action.

Authentication information remains only in page-memory closures under the patient-binding and expiry rules above; it is never written to storage. A completed FHIR Bundle may be gzip-compressed, AES-256-GCM-encrypted, and staged in extension-origin IndexedDB for at most one hour; an exact-expiry alarm and expired-read checks enforce the limit. The original MediCloud responses that produced that Bundle are stored in the same record under the same key, so "download original data" does not have to read MediCloud again; they carry the Bundle's patient binding and expiry and are cleared together with it under the same conditions, including when a patient switch is detected. Before any original-data download is released, the patient currently shown in MediCloud is re-verified; if it no longer matches, the staged copies are cleared and nothing is written. A raw download taken without first running a conversion is processed in memory only and is not retained. unlimitedStorage supports large Bundles beyond the session-storage quota. Its decryption key exists only in chrome.storage.session. If IndexedDB is unavailable, an encrypted result of at most 3 MiB may be staged in session storage instead, with the same patient binding, expiry and clearing rules. Oversized optional raw responses may be omitted from this fallback; the primary result is never truncated. The extension creates no persistent consent record; since v0.5.6 it deletes the legacy two-field consent record on startup. Apart from that compatibility cleanup, it does not use chrome.storage.local or chrome.storage.sync for patient, health, or consent data.

If conversion fails after source responses have been obtained, those responses may also be compressed, encrypted and retained for a raw download after another same-patient check. The same one-hour maximum, patient binding and clearing rules apply. Cancelled or mismatched-patient jobs do not retain them.

De-identification and integration preferences, trusted-source identifiers and the validated MediPrisma destination are stored in chrome.storage.local until changed or cleared, or the extension is removed. Legacy localStorage de-identification preferences may be migrated during an upgrade; failed migration or preference reads retain masking. These preferences do not contain clinical records and are not synchronized through chrome.storage.sync.

Downloaded files are controlled by the user and their organization. The publisher cannot access or delete them.

5. Security and user choices

The extension uses exact host permissions, HTTPS, repeated authoritative patient-context checks at data egress, short-lived state, restricted session storage, packaged code only, and a narrow MediPrisma handoff context. The current private/internal build still contains a fixed encrypted MediPrisma credential with replay risk; it must be revoked and replaced by a server-minted single-use token before production release. Users may choose not to start capture, not to use MediPrisma, or to remove the extension. Users should never send real patient records, full identifiers, credentials, or tokens through public support channels.

6. Clinical limitation

MediCloud data and the extension's output are clinical reference information, not a diagnosis, treatment recommendation, or official medical record. Users must follow authoritative sources, professional judgment, and their organization's approval, confirmation, signature, and retention processes.

7. Limited Use statement

The use of information received by this extension will adhere to the Chrome Web Store User Data Policy, including the Limited Use requirements. User data is used only for the disclosed single purpose and is not sold, used for personalized advertising, provided to data brokers, or used for creditworthiness or lending.
